# Практика Java — сломанный инвентарь

Игровой инвентарь запускается, но неправильно обрабатывает повторные коды, поиск и использование зелий. Восстановите его работу и отправьте исправления из своего форка на проверку преподавателю.

## Новое в Java

Перед началом прочитайте [теорию с примерами](THEORY.md). Она объясняет, как устроены классы в задании, как выбрать коллекцию и как отправить решение из своего форка.

- `Map<String, Item>` хранит пары «код — предмет». Выберите реализацию `Map`, которая сохраняет порядок добавления.
- `Optional<Item>` позволяет явно показать, найден ли предмет. Изучите, как создать пустой результат и извлечь предмет, если он найден.
- `List<String>` может быть снимком списка кодов. Разберитесь, как защитить список от изменений и почему снимок должен сохранять прежнее содержимое после изменения инвентаря.

Документация Java 17: [Map](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/Map.html), [LinkedHashMap](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/LinkedHashMap.html), [Optional](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/Optional.html) и [List](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/List.html).

## Требуемое поведение

1. У каждого `Item` есть неизменяемый код и имя. Конструктор отклоняет `null`, пустой код и код только из пробельных символов с помощью `IllegalArgumentException`. Остальные коды хранятся как переданы. Имя может быть пустым, но `null` отклоняется с помощью `NullPointerException`. Отрицательное количество в конструкторе и `setQuantity` превращается в 0.
2. `Item.use()` возвращает `Item: <имя>`, а `Weapon.use()` возвращает `Attack: <имя>`. Количество не меняется. При положительном количестве `Potion.use()` уменьшает его на 1 и возвращает `Drink: <имя>`. При нуле возвращает `Empty: <имя>` и оставляет количество равным 0. После двоеточия везде один пробел.
3. `Inventory.add(item)` возвращает `true` при добавлении. Для `null` и для повторного кода возвращает `false` без изменений. Коды сравниваются по содержимому с учётом регистра. Разные коды могут иметь одинаковое имя. `getSize()` возвращает число зарегистрированных предметов.
4. `findByCode(code)` возвращает `Optional` с исходным объектом предмета. Для отсутствующего кода и `null` возвращает пустой `Optional`.
5. `removeByCode(code)` возвращает `true` при удалении и `false` для отсутствующего кода или `null`. Остальные предметы сохраняют порядок. Если код добавлен снова после удаления, он появляется в конце.
6. `listCodes()` возвращает неизменяемый снимок кодов в порядке добавления. Ранее полученный список сохраняет своё содержимое и после добавления, удаления или очистки инвентаря. Для пустого инвентаря список пуст.
7. `useAll()` вызывает `use()` ровно один раз для каждого предмета в порядке добавления. Возвращает сообщения в том же порядке. Для пустого инвентаря список сообщений пуст.
8. `clear()` удаляет все записи. Повторная очистка безопасна.

## Сборка и запуск

Понадобятся Git и JDK 17 или новее. Выполните команды из каталога проекта. Они подходят для PowerShell и Bash.

```sh
javac --release 17 -encoding UTF-8 -d out -sourcepath src src/inventory/InventoryDemo.java tests/inventory/InventoryTests.java
java -cp out inventory.InventoryDemo
java -cp out inventory.InventoryTests
```

Часть тестов на исходнике намеренно падает. Например, демонстрация дважды сообщает `Drink: Potion`, хотя зелье было одно. После исправлений второй вызов должен вернуть `Empty: Potion`.

## Что сделать

1. Сделайте форк и создайте свою ветку по инструкции ниже. Запустите демонстрацию и тесты, запишите первые расхождения с условием.
2. Исправьте поведение предметов и инвентаря. Внутри `Inventory` храните предметы в `Map<String, Item>`. Сохраните публичные сигнатуры и переопределения с `@Override`.
3. Дополните `InventoryTests.java`. Проверьте `null` при добавлении и удалении, одинаковые имена у разных кодов, различие регистра, очистку, удаление и повторное добавление. Проверьте также отрицательное количество и снимок кодов: попытка изменить список должна дать `UnsupportedOperationException`, а изменение инвентаря не должно менять старый список. Сохраните исходные проверки.
4. Приведите исходники в `src`, включая `InventoryDemo.java`, и тесты в `tests` в соответствие с [действующим кодстайлом курса Java](https://github.com/Flovwvers-students/java-course-materials/blob/main/code-style/Java_Code_Style.txt). Исправьте нарушения в стартовом коде и соблюдайте правила в новом коде. Сохраните публичные сигнатуры и все исходные проверки.
5. Создайте `REPORT.md` с ФИО, группой, описанием ошибок и их причин, исправлениями и результатами тестов. Объясните, почему выбрали свою реализацию `Map`, чем пустой `Optional` отличается от `null` и как тест подтверждает, что список кодов является снимком.

## Как сдать через форк и Pull Request

### 1. Сделайте форк и скачайте его

Откройте [задание на GitHub](https://github.com/Flovwvers-students/java-broken-inventory), нажмите **Fork**, в поле **Owner** выберите личный аккаунт и нажмите **Create fork**. Оставьте имя `java-broken-inventory`. Под названием вашего репозитория должна появиться ссылка **forked from Flovwvers-students/java-broken-inventory**.

На странице своего форка откройте **Code → HTTPS** и скопируйте адрес. Подставьте свой логин в пример ниже. Для ветки используйте свою фамилию и имя латиницей через дефис, например `ivanov-ivan`.

```sh
git clone https://github.com/YOUR-LOGIN/java-broken-inventory.git
cd java-broken-inventory
git switch -c ivanov-ivan
git remote -v
```

В выводе `git remote -v` у `origin` должен быть адрес вашего форка. На следующем занятии откройте существующую папку и переключитесь на свою ветку.

### 2. Отправьте исправления в свой форк

Запустите тесты, затем проверьте состав изменений. В коммит входят исходники, тесты и отчёт. Каталог `out` и файлы `.class` игнорируются.

```sh
git status
git add src tests REPORT.md
git diff --cached
git commit -m "Fix Java inventory and add tests"
git push -u origin ivanov-ivan
```

### 3. Откройте Pull Request

В [исходном репозитории](https://github.com/Flovwvers-students/java-broken-inventory/pulls) нажмите **New pull request**, затем при необходимости **compare across forks**. Проверьте поля:

| Поле | Что выбрать |
| --- | --- |
| base repository | `Flovwvers-students/java-broken-inventory` |
| base | `main` |
| head repository | `ВАШ-ЛОГИН/java-broken-inventory` |
| compare | Ваша ветка, например `ivanov-ivan` |

Убедитесь, что видны ваши изменения, нажмите **Create pull request** и заполните шаблон. Пример заголовка — «Иванов Иван — группа НАЗВАНИЕ — Инвентарь Java». Сохраните ссылку на PR. Форк и PR этого задания публичные.

Если преподаватель оставит замечания, исправьте их в той же ветке, снова прогоните тесты и отправьте новый коммит через `git push`. Он появится в уже открытом PR. После приёмки преподаватель сообщает результат и закрывает PR без слияния, чтобы исходное задание осталось доступно следующей группе.

Справка GitHub: [создание форка](https://docs.github.com/en/pull-requests/how-tos/work-with-forks/fork-a-repo) и [Pull Request из форка](https://docs.github.com/en/pull-requests/how-tos/create-pull-requests/creating-a-pull-request-from-a-fork).
