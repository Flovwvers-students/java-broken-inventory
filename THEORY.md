# Теория к практике «Сломанный инвентарь»

Если вы уже писали классы и работали со списками, начните с раздела про `Map`. Примеры ниже используют книжный каталог. Перенесите эти идеи на игровой инвентарь самостоятельно.

## Классы, объекты и переопределение

Класс описывает поля и методы, а конструктор задаёт начальное состояние нового объекта. `private` ограничивает прямой доступ к полю из других классов. Через геттер можно прочитать значение, а через сеттер — изменить его с проверкой. Полю `final` можно присвоить значение только один раз. В задании так хранится код предмета, чтобы он не менялся после добавления в инвентарь.

Класс `Potion` наследует `Item` через `extends`. Вызов `super(...)` передаёт параметры конструктору родительского класса. Аннотация `@Override` просит компилятор проверить, что метод действительно переопределяет унаследованный метод.

В строке `Item item = new Potion("healing", "Potion", 1);` переменная имеет тип `Item`, а объект — тип `Potion`. При вызове `item.use()` Java выберет реализацию `Potion`. Если метод изменит количество, изменится состояние этого же объекта. Такое поведение позволяет обрабатывать разные предметы через общий тип `Item`.

## Ссылки, строки и списки

Переменная объектного типа хранит ссылку. Значение `null` означает, что ссылка не указывает на объект. Вызов метода через такую ссылку приводит к `NullPointerException`.

Для объектов `==` проверяет, указывают ли ссылки на один объект. У строк `equals()` сравнивает текст с учётом регистра.

```java
String firstCode = "B-17";
String secondCode = new String(firstCode);

System.out.println(firstCode == secondCode);      // false
System.out.println(firstCode.equals(secondCode)); // true
```

Выражение `new String(...)` здесь специально создаёт второй объект с тем же текстом. Подумайте, какой вид сравнения подходит для поиска по коду.

`List<String>` — список строк. Параметр в угловых скобках задаёт тип элемента. Цикл `for (String code : codes)` перебирает элементы списка по порядку.

## Map и порядок добавления

`Map<K, V>` хранит пары «ключ — значение». Вместо `K` указывают тип ключа, вместо `V` — тип значения. В каталоге `Map<String, String>` может связывать код книги с её названием. Одному ключу соответствует одна запись. У разных ключей могут быть одинаковые значения.

- `put(key, value)` добавляет запись или заменяет значение у существующего ключа.
- `containsKey(key)` проверяет, есть ли ключ.
- `get(key)` возвращает значение. Если ключа нет, возвращается `null`.
- `remove(key)` удаляет запись. `keySet()` даёт доступ к ключам, а `values()` — к значениям.

`HashMap` не гарантирует порядок обхода. `LinkedHashMap`, созданный обычным конструктором, обходит записи в порядке добавления. Замена значения у существующего ключа сохраняет его позицию. Если удалить ключ и добавить его заново, он окажется в конце.

Попробуйте предсказать результат. Для примера нужны импорты `java.util.LinkedHashMap` и `java.util.Map`.

```java
Map<String, String> catalog = new LinkedHashMap<>();
catalog.put("B-17", "Атлас");
catalog.put("A-02", "Словарь");
catalog.put("B-17", "Новый атлас");

System.out.println(catalog.keySet());    // [B-17, A-02]
System.out.println(catalog.get("B-17")); // Новый атлас
```

Сравните поведение `put` с условием задания при повторном добавлении кода.

## Optional и результат поиска

`Optional<T>` может содержать значение типа `T` или быть пустым. Метод, который возвращает `Optional`, при отсутствии значения возвращает `Optional.empty()`.

- `Optional.ofNullable(value)` оборачивает значение и возвращает пустой `Optional`, если получил `null`.
- `isPresent()` сообщает, есть ли значение. `isEmpty()` проверяет обратное.
- `orElse(fallback)` возвращает найденное значение или значение по умолчанию.
- `get()` у пустого `Optional` выбрасывает исключение. Прежде чем вызывать его, нужно проверить наличие значения.

Продолжение примера с каталогом. Добавьте импорт `java.util.Optional`.

```java
Optional<String> title = Optional.ofNullable(catalog.get("Z-99"));
System.out.println(title.orElse("Книга не найдена"));
```

## Неизменяемый снимок

У снимка списка два свойства. Попытка добавить или удалить элемент через сам список вызывает `UnsupportedOperationException`. Если позже изменить исходную коллекцию, ранее полученный снимок сохраняет свой состав.

Например, `Collections.unmodifiableList(source)` запрещает правки через полученный список, но отражает изменения `source`. `List.copyOf(source)` возвращает неизменяемый снимок состава. Если внутри находятся изменяемые объекты, снимок сам по себе их не копирует. Для списка кодов это не проблема, потому что строки в Java неизменяемы.

Проверьте оба свойства отдельными тестами. Сначала попытайтесь изменить полученный список. Затем измените исходную коллекцию и сравните старый список с ожидаемым содержимым.

## Порядок проверки и выполнения

Представьте, что программа выдаёт читателю несколько книг по списку кодов. Сначала она выясняет, есть ли в каталоге каждая книга, и запоминает найденные экземпляры. После успешной проверки она отмечает выдачу в порядке запроса. Если начать выдавать книги прямо во время поиска, отсутствующая последняя книга обнаружится после выдачи предыдущих.

Для списка результатов поиска полезно различать состав и состояние. Список может хранить те же объекты, даже если запись впоследствии убрали из каталога. Поля самих объектов по-прежнему можно изменить через доступные методы. В тесте сравните состав списка после удаления записи, а состояние объекта — после изменения его поля.

Пустой `Optional` обозначает отсутствие результата. `Optional.of(List.of())` содержит успешный результат с нулём элементов. Разделите эти случаи в тестах.

## Как читать падающий тест

`expected` показывает результат, который требует тест, а `got` — то, что выдал код. Найдите вызов метода, к которому относится расхождение. Например, если второй вызов `useAll()` снова сообщает об использовании последнего зелья, посмотрите, как менялось количество после первого вызова. После исправления запустите весь набор тестов.

## Форк, ветка и Pull Request

| Действие | Что происходит |
| --- | --- |
| **Fork** | На GitHub появляется связанная с исходным репозиторием копия под вашим аккаунтом. |
| `git clone` | На компьютере появляется рабочая копия. Если клонировали свой форк, адрес `origin` ведёт в него. |
| `git switch -c` | Создаётся отдельная ветка для вашего решения. |
| `git commit` | Подготовленные изменения сохраняются в истории локальной ветки. |
| `git push` | Коммиты отправляются в ветку вашего форка на GitHub. |
| **Pull Request** | GitHub показывает преподавателю изменения между вашей веткой и `main` исходного репозитория. |

Перед первым `push` посмотрите адрес `origin` через `git remote -v`. При создании PR выберите ветку `main` исходного репозитория в поле **base**, а свою ветку из форка — в поле **compare**. Посмотрите список изменений, прежде чем отправить работу на проверку. Точные команды приведены в [инструкции по сдаче](README.md#как-сдать-через-форк-и-pull-request).
